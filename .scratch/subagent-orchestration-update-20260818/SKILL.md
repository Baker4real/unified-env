# Subagent Orchestration

仅在用户显式调用 `$subagent-orchestration` 时使用。开始前完整读取
`D:\Codex\.codex\docs\agent-guidance\reasoning-and-adversarial-review.md`；该文档是任务契约、隐私、审查和降级规则的单一事实源。本 skill 只规定任务路由与执行顺序。

下文的 `spawn_agent`、`list_agents` 是 Codex 接口名。在 Claude Code 上运行时，先读
[`references/claude-code.md`](references/claude-code.md) 换用该 harness 的调度接口、容量记账、递归深度上限、只读工具边界和验收机制。

## 建图与路由

1. 写清任务目标、已核验事实、主要 failure modes、可失败完成证据、范围、不可触碰对象，以及破坏性、外发或 GUI 操作所需的独立授权。
2. 按工作类型画出最小任务依赖图：
   - 实现节点切成 tracer-bullet 纵向切片：每个节点以一个新上下文可完成、可独立演示或验收的最小端到端行为为界，不按 schema、API、UI、测试等技术层横切。
   - 调查或审查节点按相互独立、可证伪的问题、竞争假设或正交维度切，不强套纵向切片。
   - 只有为后续切片建立可验证 seam 或互斥 ownership 所必需时，才把 prefactor 设为前置 blocker；不把顺手重构扩成节点。
   - 每条 blocking edge 必须真正阻止后继开工。每个节点只包含一个目标，并标明输入、唯一 ownership、只读对象、blockers、验收和返回格式；不要为了占满槽位拆分顺序任务。
3. 按下列顺序选择执行分支：
   - 两个以上问题可独立调查，但共享写入或最终补丁必须统一时，走“只读并行，单点写入”。
   - 两个以上实现节点没有共享可变状态、具有互斥 ownership，且依赖可明确分波次时，走“完整分发”。
   - 不满足以上条件时保持单代理串行，不制造并行。
4. 只向子代理提供最小充分且已脱敏的上下文。凭据、私人联系或支付信息、无关会话状态，以及无法安全脱敏的原始数据留在主 Agent 内联处理。

广域机械重构是纵向切片的例外。单个纵向节点无法保持可验证状态时，按 expand -> migrate -> contract 建图：expand 先引入兼容的新形态，migrate 按互斥 ownership 分批迁移，contract 阻塞于全部 migrate 并删除旧形态。

两条分支共享同一外发边界：worker 及其后代不 commit/push；整棵代理树都不创建 branch/worktree、不打开 PR、不 push、不发布 issue 或其他外部更新，也不使用 browser/desktop control。完整分发中的写入授权只覆盖任务契约 ownership 内的共享工作区文件，下级委派不会隐式继承或扩大上述动作授权；任务确需这些动作时，停在已验证的共享工作区结果并单独确认。

完成标准：每个已调度节点都能在不猜测共享状态的情况下独立验收，且分支选择可由依赖图解释。

## 只读并行，单点写入

1. 按独立问题派发只读 worker；每份 brief 指定目标路径或命令，并限制返回为事实、引用、未知和风险。
2. 要求 worker 及其后代保持只读、不生成产物。worker 只有在调查仍包含可独立并行节点、且自己能继续推进不重叠工作时才继续委派；其任务契约、只读边界和结果回收责任必须传递给后代。需要变更时只报告最小候选位置与证据。
3. 等待所有已调度只读子树返回或显式取消，再由主 Agent 对照真实源码消解矛盾、去重并保留未解决不确定性。
4. 只由主 Agent 写入统一补丁、运行验证并复核实际 diff。高风险或跨模块交付在收口前另行调度独立只读 reviewer/verifier。

完成标准：所有 worker 状态已终结，主 Agent 是唯一写入者，禁止的 branch/worktree/PR/push/外部或 GUI 动作均未发生，统一补丁与测试均由主 Agent 重新验证。

## 完整分发

1. 在每个 wave 前，由准备派发的 Agent 调用真实 collaboration 状态接口（例如 `list_agents`），以整棵会话树当前运行代理和运行时公布的容量为准；为根 Agent 或仍在运行的关键协调路径保留槽位，不沿用上一个 wave 的容量假设。
2. 只调度 frontier，即 blockers 已全部满足的节点。独立节点同 wave 分发，有依赖的节点等待前置验收后串行进入后续 wave；整棵任务树中同一文件、模块或外部资源同时只有一个 owner。
3. 通过真实 `spawn_agent` 接口派发，并记录接口返回的 canonical task name 或 task id。普通 shell/本地工具调用不构成调度证据。子代理可在自己的任务契约内继续派发新的、具体、有界且可独立推进的节点，并成为其直接子节点的协调者；不得只为转述原任务或制造层级而委派。
4. 每份任务契约遵循全局协议，并明确禁止范围、共享工作区提示、依赖等待点、下级委派边界、验证命令和 `DONE` / `DONE_WITH_CONCERNS` / `BLOCKED` / `NEEDS_CONTEXT` 返回格式。写入 worker 及其后代只能修改各自 ownership 内文件。
5. 每个协调者在等待时继续自己不依赖后代的工作，收到结果后复读实际文件、diff、命令输出和测试，再向父级返回；根 Agent 复核最终集成，不得只依据任何层级的摘要接受实现。
6. 实现 wave 结束后，调度未参与实现且保持只读的 reviewer 攻击边界、回滚和测试缺口，再由另一名 verifier 确认高影响发现及完成证据。容量不足时串行调度这两个角色，不降低独立性。
7. 在交付前等待所有已调度 worker、reviewer 和 verifier 返回，或通过真实接口显式取消并记录状态；整合已验证发现，重跑统一验收。

完成标准：任务树全部终结，ownership 无冲突，真实调度标识齐全，每个协调者已验收直接子节点，独立 reviewer/verifier 已收口，根 Agent 已核对实际改动和测试。

## 确定性回退

| 触发条件 | 第一修复 | 仍失败时 |
| --- | --- | --- |
| 实时容量不足 | 等当前 wave 或无关子树终结后重新读取容量，按依赖串行派发。 | 当前协调者收回未派发节点串行完成，并向父级如实报告。 |
| `spawn_agent` 返回错误 | 保留真实接口错误和未调度节点，不用本地命令冒充派发。 | 当前协调者收回该节点串行执行。 |
| 运行时拒绝继续下级委派，例如旧 V1 的深度限制或当前策略限制 | 当前协调者收回该节点并在现有任务内完成，不尝试绕过运行时限制。 | 向父级返回受限证据和未完成边界，由上层重新安排。 |
| 依赖或 ownership 不清 | 停止相关派发，缩小节点并指定唯一 owner。 | 合并为当前协调者的单一串行节点。 |
| migrate batch 无法独立验收，或与其它 batch 的 ownership 重叠 | 缩小 batch 或改为串行迁移。 | 合并为单一 owner；不得借此创建 integration branch/worktree，确需时单独取得用户授权。 |
| worker 越界写入，或下级委派破坏权限、ownership 或容量边界 | 立即停止相关子树，复读共享状态并隔离其结论。 | 上级协调者恢复到已验证边界；需要破坏性恢复时先取得授权。 |
| worker 失联或结果矛盾 | 查询真实状态，等待或显式取消；回到引用源码核验。 | 把该节点标为 unresolved，不让未经验证结论进入补丁。 |
| 原始数据无法安全脱敏 | 不派发原始数据，在主 Agent 内联处理。 | 说明隐私限制和残余审查风险。 |
| reviewer/verifier 工具不可用 | 保留实现结果，按全局协议检查工具状态并延后串行复核。 | 主 Agent 内联执行同一对抗清单，明确缺少独立复核，不声称完整分发闭环。 |
